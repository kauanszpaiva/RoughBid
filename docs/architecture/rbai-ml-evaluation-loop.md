# RB.AI ML Evaluation and Learning Loop

## Purpose

RoughBid must not improve plan-reading quality by changing prompts or models without a measurable benchmark. The first ML foundation is a task-level evaluation layer that can compare a new RB.AI pipeline against a frozen ground-truth set without mixing revisions of the same construction project between training and evaluation.

This layer is deliberately isolated from production inference, pricing catalogs, billing, and the Plans UI. It can be merged while the Plans Workspace and estimating-catalog work continue independently.

## Architecture direction

RB.AI should remain a hybrid system:

1. PDF/vector extraction and OCR recover source facts.
2. Geometry and scale logic calculate measurable quantities deterministically when evidence is sufficient.
3. Multimodal providers interpret legends, notes, schedules, disciplines, conflicts, and ambiguous visual context.
4. Pricing remains source-dated, geography-aware, and reproducible rather than generated by an LLM.
5. Human review creates corrected labels/quantities that can become future training examples when rights and provenance permit.
6. Every candidate model/prompt/pipeline version is evaluated against frozen benchmarks before rollout.

## Benchmark V1 contract

`apps/api/src/ml/benchmark.ts` accepts `rbai-benchmark-v1` JSON with:

- `split.trainProjectFamilyIds`
- `split.evaluationProjectFamilyIds`
- `classification[]`
- `quantities[]`
- optional `quantityTolerancePercent`

Version-qualified identifiers may use `document-version:project-family`, for example `permit-set:job-123` and `addendum-2:job-123`. The evaluator rejects a project family that appears on both sides of the split.

### Sheet classification

Tracked metrics:

- accuracy;
- macro precision;
- macro recall;
- macro F1;
- per-label support/precision/recall/F1;
- expected calibration error (ECE).

Macro metrics are required because uncommon disciplines must not disappear behind a high-volume architectural class.

### Quantity takeoff

Tracked metrics:

- mean absolute error (MAE);
- mean absolute percentage error (MAPE) only where ground truth is non-zero;
- within-tolerance rate;
- per-unit slices;
- confidence calibration against tolerance-qualified correctness.

A default 5% tolerance is a benchmark parameter, not a claim that every trade or quantity can safely use the same tolerance. Future benchmark versions should support trade- and quantity-specific tolerances.

## Leakage rules

Do not split permit sets, bid sets, addenda, revisions, or near-duplicate sheets from the same underlying project across train and evaluation. Dataset splits must be project-family based. At least one production benchmark should later be chronological so the model is tested against projects newer than its training corpus.

## Data-rights rule

Do not vendor, train on, or redistribute third-party floor-plan repositories, drawings, datasets, or model weights solely because they are publicly accessible. Record license/training permission and provenance first. The uploaded research pack contains useful technical references, but repositories with missing or unclear licenses remain reference-only until reviewed.

## How to run

Create a benchmark JSON file and run:

```bash
node --experimental-strip-types scripts/ml/evaluate-blueprint-benchmark.ts path/to/benchmark.json
```

The command emits a machine-readable `rbai-benchmark-report-v1` JSON report and exits non-zero for invalid input or split leakage.

## Next integration steps

1. Define a canonical reviewed-finding export from accepted/rejected/corrected plan-reading findings.
2. Add a rights/provenance ledger for every training/evaluation source.
3. Build a frozen internal corpus from KSP-owned or explicitly permitted plans and estimator corrections.
4. Add geometry/source-grounding metrics (IoU, localization recall, scale error, dimension exact match).
5. Add estimate-level metrics only after quantity and pricing provenance can be evaluated separately.
6. Gate provider/prompt/model changes on benchmark deltas and worst-slice regressions, not only global averages.
7. Add active-learning queues that prioritize low-confidence/high-impact findings for human review.

## Release rule

This foundation does not claim that RB.AI is trained or more accurate by itself. It creates the measurement contract required to prove future ML improvements safely. Production inference remains unchanged until a candidate pipeline is benchmarked and separately approved.
